# Local MPI/OpenMP launcher

Run local CP2K calculations on separate physical cores, coordinating jobs of the same user. Start
each calculation in its own working directory:

```shell
export PATH=/path/to/cp2k/tools/local_run:$PATH
cp2k_local.py -h                 # --help is equivalent
# Terminal A: CLI ranks, environment threads
OMP_NUM_THREADS=3 cp2k_local.py -n 2 -- cp2k.psmp -i input.inp
# Terminal B: environment ranks, CLI threads
MPI_RANKS=2 cp2k_local.py -t 3 -- cp2k.psmp -i input.inp
# Or use an absolute path without changing PATH:
/path/to/cp2k/tools/local_run/cp2k_local.py -n 2 -t 3 -- cp2k.psmp -i input.inp
```

Requires Linux, Python 3.9+, **Open MPI 5**, matching `hwloc-calc`, and GNU OpenMP (libgomp). Use
`--mpirun /path/to/mpirun` to select MPI; `hwloc-calc` is found beside it or in PATH. Use
single-level OpenMP without conflicting affinity or thread-limit settings; BLAS settings remain
under your control.

Ranks and threads resolve independently:

- MPI ranks: `-n`/`--ranks` > `MPI_RANKS` > **1**.
- Threads per rank: `-t`/`--threads` > `OMP_NUM_THREADS` > **1**.

Only the selected value must be a positive integer; empty values and lists such as `4,2` are
invalid. Valid CLI values override invalid environment values. `MPI_RANKS` is a CP2K convention, not
a general MPI variable.

The launcher respects online CPUs and the caller's allowed CPU mask, selecting one hardware thread
per physical core. An Open MPI rankfile and `OMP_PLACES=threads`, `OMP_PROC_BIND=close` bind each
computing thread to one logical CPU. Same-user jobs sharing `/tmp` reserve whole SMT sibling groups
with exclusive locks, automatically released on normal exit. Capacity shortages fail immediately.
`--dry-run` shows the topology and planned CPUs without running.

For a single calculation, you can also use standard Open MPI 5 placement directly:

```shell
# Pure MPI: two ranks, one OpenMP thread and one physical core per rank.
OMP_NUM_THREADS=1 OMP_PLACES=cores OMP_PROC_BIND=close OMP_DYNAMIC=FALSE \
  mpirun --host localhost:2 -n 2 --map-by core --bind-to core --report-bindings \
  cp2k.psmp -i input.inp
# Hybrid: two ranks, three OpenMP threads and three physical cores per rank.
OMP_NUM_THREADS=3 OMP_PLACES=cores OMP_PROC_BIND=close OMP_DYNAMIC=FALSE \
  mpirun --host localhost:2 -n 2 --map-by slot:PE=3 --bind-to core --report-bindings \
  cp2k.psmp -i input.inp
```

Core placement allows SMT siblings in each thread's mask. For exact singleton CPU masks, use
hwthread/rankfile placement, as generated by the launcher. Independent bare `mpirun` jobs do not
coordinate core selection; the launcher coordinates participating jobs of the same user.

This tool is for a single local Linux node outside schedulers. On shared clusters, use the site's
existing Slurm allocation and MPI launch policy. Other MPI/OpenMP runtimes and CPU hotplug are
outside the supported scope; WSL uses guest-exposed topology.

Validated on Linux/WSL with Open MPI 5.0.8, hwloc 2.12.1 and GNU libgomp: six unit tests and
concurrent 2-rank × 3-thread affinity probes passed, including complementary SMT views. The standard
commands above were also checked with `affinity_probe.c`; this is placement validation, not CP2K
numerical validation.
